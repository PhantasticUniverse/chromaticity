# Parity Coverage Matrix

This matrix is a read-only claim-hygiene companion to `26-evidence-artifact-registry.md`. It maps observed reference-behavior families to the current Chromaticity coverage posture so reviews can see what is implemented, what is planned under an evidence row, what is post-MVP, and what is intentionally rejected. Status vocabulary is `implemented`, `planned:<EV-ID>`, `post-MVP`, `intentionally-rejected`, and `n/a`; if no valid evidence row exists yet, use `planned:gap:<description>` so the gap can be triaged without inventing an EV-ID. Every `planned:<EV-ID>` row must cite an EV-ID that exists in `26-evidence-artifact-registry.md`; run `bash scripts/evidence-tag-lint.sh` after edits to keep the EV namespace valid. This matrix is not a gate. It is a coverage index; gate authority stays with `26-evidence-artifact-registry.md` for the release cumulative gate and `11-roadmap-phases.md` for phase-exit gates. Bare spec filenames in the Reference column resolve under `docs/governance/` (`03`, `11`, `26`, `28`, `30`, `31`, `34`, `43`), `docs/architecture/` (`02`, `04`-`08`, `10`, `22`, `32`, `37`, `38`), or `docs/adr/` (`adr/ADR-*`).

> **Status Legend:** 🟢 `implemented` · 🟡 `planned:*` · ⚪ `post-MVP` · ➖ `intentionally-rejected` / `n/a`
