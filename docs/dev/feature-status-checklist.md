# Feature Status — Master Checklist

This is a living, repo-wide snapshot of every surveyed feature's implementation status,
a defensible 0–10 quality rating, and an honest real-vs-synthetic accounting. It is an
engineering field map, **not** a gate record.

- **Last surveyed:** 2026-06-05
- **Scope:** 11 lanes (audio, render, runtime, scene-authoring, integrations-io,
  data-ingest, entitlement, observability, ui-views, ui-widgets-ipc,
  release-docs-policy).

## How this was built + trust caveat

This checklist was assembled from a multi-agent survey of the tree (one agent per lane,
each reading source + running the relevant tests) followed by an adversarial critique
pass that spot-checked the highest-stakes false-pass risks and completeness gaps. Where
the critique corrected a rating, status, or evidence line, the corrected value is used
and flagged with `(adj.)` in the Notes column.

Caveats you must hold:

- **Ratings are defensible-against-tree judgments, not gate decisions.** A 9/10 means
  "production-grade for its declared scope as verified in-tree," not "EXIT-gated Pass."
- **`docs/26-evidence-artifact-registry.md` is the authoritative formal status.** When a
  registry row and this checklist disagree on Pass/Planned/InProgress, the registry wins
  for governance purposes; this doc records the *implementation reality* the surveyors
  could verify.
- **The tree wins over this doc.** If a file ref, status, or claim here disagrees with
  the code, the code is right and this file is stale — fix it in a follow-up
  `docs(repo)` commit (see Maintenance).

## Legend

**Status enum:**

- **shipped** — live, wired end-to-end, production-real for its declared scope.
- **live-partial** — real and wired, but with a documented narrowing (a synthetic
  sub-path, a deferred axis, or a stale/cosmetic edge).
- **scaffolded** — real types/traits/tests exist, but no production caller wires them
  into the running app; pure structure awaiting a consumer.
- **synthetic-only** — exercises real code against synthetic inputs in a harness/corpus;
  not a user-facing live path.
- **stub** — visual/structural shell with little or no real behavior behind it.
- **deferred** — partial implicit handling only; the feature is explicitly held back.
- **planned** — absent from the tree; documentation/reservation only.

**Rating rubric (0–10):** 0 = absent; 1–2 = placeholder/permission-scaffolding;
3–4 = real shell or orphaned/un-wired logic; 5–6 = real logic with a material narrowing
or no live consumer; 7–8 = production-grade, wired, tested; 9–10 = best-in-class,
hardware/corpus-verified, with only minor documented gaps.

### Headline

The **audio**, **scene-authoring (engine)**, **runtime scheduler/state**, and
**ui-widgets-ipc** lanes are the most mature: capture → AGC bands → FFT/BPM → producer
runtime → IPC bridge → DAW-grade metering is live end-to-end (150 Rust + 64 frontend
tests), the deterministic scheduler/state/migration/crash-resume core is wired into the
60 Hz commit thread, and the control/snap/preset/settings/MIDI/OSC IPC seams round-trip
into the engine command bus. The **render** GPU pipeline (wgpu 26 + naga, multipass,
feedback ping-pong, GPU crossfade) is production-grade and hardware-verified on Apple
Silicon Metal — but live rendering is only at R-1a (an env-gated window presenting a
hardcoded test pattern); the in-app Perform preview is still canvas-2d procedural.

The biggest gaps cluster in three places: (1) the **entitlement** lane is a
well-tested *library with zero runtime callers* — `entitled()` is never invoked,
the capabilities store is fixture-seeded, License IPC returns `not implemented`, and
Ed25519 signature verification is entirely unbuilt; (2) the **data-ingest** lane is
100% post-MVP ADR-017 reservation (forward-compat namespace squatting only); and
(3) the **release pipeline** is scaffold/stub-only with all real cert work AO-gated and
unverified on hardware. Several UI views (Playlist, Patch, Import, Sources) are
wireframe-faithful but engine-disconnected, and the 57-row hotkey vocabulary has only
3 production keydown listeners.

## Top gaps & next-up

Prioritized from low ratings, the critique's false-pass observations, and the
"what-remains-synthetic-only" reality:

- **Entitlement enforcement has no runtime caller.** `entitled()` / `is_valid_at()`
  have zero external call sites; the UI capabilities store is fixture-seeded; the
  watermark/LockedRow gating reads that fixture, not a live `EntitlementBitmask`. The
  whole lane is corpus-proven, not user-functional. The registry's "adapter-boundary
  enforcement" framing diverges from the tree (free functions, no caller) — tree wins.
- **Ed25519 signature verification is unbuilt.** The load-bearing security primitive
  (signature over canonical CBOR + blake3 machine binding) is absent — a forged token
  with placeholder bytes deserializes and passes `entitled()` identically to a real one.
- **`snapshot.degraded` is hardcoded `false` at the audio producer** (`runtime.rs:519`).
  The negotiator has a Degraded state machine the runtime never reads, so the UI AUDIO
  pill's degraded state can only fire from a hand-injected payload, never from a genuine
  engine ingest-degradation.
- **macOS system-audio IOProc tap is implemented + reviewed but NOT hardware-verified.**
  ADR-022 Amendment + `UPSTREAM-VERSION.md` name on-hardware sine-probe verification as
  "the remaining gate." CLAUDE.md's "hardware-verified clean raw_peak=0.5" claim is
  uncorroborated in the tree.
- **Live render is only R-1a.** The GPU pipeline is production-grade but only renders a
  hardcoded test pattern behind `CHROMA_RENDER_OUTPUT`; the Perform preview is canvas-2d
  procedural; the scheduler `RenderDispatch` seam has no production implementor; the
  shader cache is architecturally orphaned from `multipass.rs` (recompiles per tick).
- **Hotkey vocabulary is data-only at runtime.** 57 rows exist as data + a read-only
  overlay, but only `?`, `Cmd+K`, and `Cmd+\` are bound app-wide — the D/R/P/L control
  bindings and the other 53 rows have no DOM listener. EV-HOTKEY-* is Pass at
  synthetic-corpus scope only.
- **Release pipeline ships no installer.** `bundle.active=false`, so the matrix builds a
  bare binary with nothing to sign/notarize/distribute; signing scripts run in stub mode;
  the updater pubkey is a literal placeholder; Sigstore attestation is permission-scaffold
  only; SBOMs are emitted but never linked into a release/attestation.
- **Engine-disconnected UI views.** Playlist (cue table), Patch (node graph), Import, and
  Sources/Media are interactive but zero-IPC fixtures; preset save + snap labels are
  in-process/localStorage only (no disk durability).
- **Data-ingest cluster is entirely planned.** ADR-017 has no normative content; all ten
  rows are Planned/pending:artifact. Only forward-compat reservations exist (DATA_SOURCES
  parse-reserve, three fail-closed `data.ingest.*` capability strings, `chroma_Data_*`
  namespace, `/data/` reserved OSC prefix).
- **Library thumbnails are unwired.** The deterministic stub renderer is not IPC-exposed
  and the grid shows a placeholder disc; GPU-backed thumbnails are post-MVP.

## Maintenance

This is a living artifact. To update it:

- **Re-run the survey workflow** that produced this doc (multi-agent per-lane survey +
  adversarial critique), then regenerate this file from the merged output. That is the
  canonical refresh path and keeps the Dashboard counts/averages honest.
- **Or edit in place** for a single feature when you touch it: update its row's Status,
  Rating, and Notes, fix the Implementation refs if files moved, and bump the
  "Last surveyed" date if you did a broad pass. Recompute the affected Dashboard cells.
- **Keep `(adj.)` flags** when a value was corrected against the tree by a critique pass;
  drop the flag only once the underlying survey is re-run and agrees.

Mirroring CLAUDE.md's "when this file is wrong" principle: **the tree wins.** If a row
here disagrees with the code, the registry (`docs/26`), or an ADR, the authoritative
source is right and this checklist is stale — correct it in a follow-up `docs(repo)`
commit. **A stale checklist is worse than none**, because it invites false confidence;
prefer deleting or flagging a row you can no longer verify over leaving an out-of-date
claim standing.
