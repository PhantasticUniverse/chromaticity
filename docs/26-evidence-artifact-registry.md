# Evidence Artifact Registry

This registry is the canonical source of truth for phase-gate evidence requirements.

## Rules
- A phase gate is passable only when all required evidence IDs for that gate are present and marked `Pass`.
- Evidence IDs are immutable. If semantics change, create a new ID and deprecate the old ID explicitly.
- Every evidence artifact must include run metadata: commit SHA, profile, fixture set, environment, timestamp, and owner.
- Registry rows are executable gate records, not documentation-only references.

## Status Model
- `Planned`: evidence defined but no valid run recorded.
- `InProgress`: validation pipeline exists and run collection is active.
- `Pass`: latest required run passed for required profile scope.
- `Fail`: latest required run failed or is incomplete.
- `Waived`: temporary exception approved under waiver policy (`23-decision-ownership-matrix.md`).

## Evidence Packet Minimums

This section defines what must be present before an evidence row may transition to `Pass`. A row may not be marked `Pass` unless the packet minimums below are satisfied.

### Global Minimums (all EV types)
- `Artifact Location` must resolve to one of: `repo-path:<path>`, `ci-run-url:<url>`, `doc-path:<path>`, or the explicit Planned-stage placeholder `pending:<artifact-class>` (e.g., `pending:ci-run-url`, `pending:doc-path`). Rows in status `Planned` MAY use the `pending:*` placeholder. Rows transitioning to `InProgress` MUST replace `pending:*` with a concrete location before the next gate decision. Rows in status `Pass` MUST resolve to a non-`pending:*` concrete location.
- `Last Passing Run` must be a dated reference (ISO 8601 timestamp or immutable run identifier). Rows in status `Planned` MAY use the placeholder `none (Planned)`. Rows in status `Pass` MUST carry a concrete timestamp or run identifier. `InProgress` rows that have had no green run yet MAY use `none (InProgress; pipeline live)` with a link to the pipeline identifier.
- Run metadata required per the registry Rules section: commit SHA, profile, fixture set, environment, timestamp, owner. `Planned` rows are exempt from run metadata until they transition out of `Planned`.
- `Approver` must match the accountable approver for that gate. For `Planned` and `InProgress` rows, the listed `Approver` is the designated approver; the recorded-approval timestamp is produced at `Pass` transition.
- Where the **Owner** column in the catalog names a human (e.g., `Xavier Butler`), the column semantic is "accountable human" per `23-decision-ownership-matrix.md`. Where it names a workcell (e.g., `AI QA/Ops Workcell`), the semantic is "responsible workcell". Both forms are valid and are distinguished by content, not by separate columns, to keep the ledger single-table.
